# 安装与执行边界

## 安装与更新

本 Skill 的可迁移安装单元是包含 `SKILL.md`、`references/`、`scripts/`、`schemas/`、`prompts/`、`examples/`、`docs/` 等目录的 `project-deepdive/` 文件夹。它在开发仓库中的位置示例是 `skills/project-deepdive/`。将整个文件夹复制到当前 Agent 宿主配置支持的 Skill 目录，并保留目录结构；安装后的目录根部必须直接包含 `SKILL.md`。具体目的地由宿主的 Skill 配置决定，本包不依赖某台开发机的绝对路径或仓库根目录。

宿主必须支持加载 Skill，并被配置为扫描你放置它的目录。安装后按宿主要求刷新或重启，再在新对话用一句普通请求确认它能读取本包；如果没有加载，先检查宿主目录与刷新方式。完整安装命令见 [README 安装说明](../README.md#安装)。

更新前先检查副本里的本地修改。Git 安装可运行 `git status --short`；工作区干净时再按宿主说明更新到选定版本。有本地修改时，先提交或备份并比较差异；复制安装则先备份旧文件夹，在旁边准备新版本并合并要保留的修改，核对新文件夹根部有 `SKILL.md` 后再切换。不要用新版本盲目覆盖含有未保存改动的副本。

把目标项目源码、生成教材和审查记录放在目标项目或用户指定的独立输出位置，不要把它们写入 Skill 安装副本来代替正式输入。

## 运行前检查

需要检查 Skill 自身时，从安装目录根部运行：

```text
python scripts/skill_selfcheck.py
python scripts/v2_selfcheck.py
```

这些命令检查包内约束和工具，不扫描目标仓库，不证明教材教学质量，也不代替用户要求的项目验证。具体任务只运行其正式契约要求且用户请求范围内的命令；不要仅因某个命令存在就运行目标项目的测试或编译。

## 输入与写入边界

每次任务都以用户指定的目标项目根目录、主题、证据和输出位置为准。Skill 安装目录只提供方法、模板、工具和 schema，不隐含任何目标项目。CLI 的参数和限制以包内对应契约及 `--help` 为准；不从历史开发记录推导必需输入。

Skill 不要求指定 AI 模型或多智能体系统。换模型或宿主时，要确保新会话能读到本包，并传递目标仓库路径、已保存的教材和进度记录；不同模型不会自动共享上下文，输出表现也可能不同。

源码解释可以直接读取目标文件。没有适配器、提取不完整或缺少正式生命周期输入时，按包内直接源码教学指南固定实际源码字节，分别进行来源核对与完整教学复核；这不会伪造正式 helper 回执。需要正式认证、材料化或发布的操作，仍须满足对应生命周期自己的真实输入和复核门槛。

按用户授权写入指定输出位置。默认不安装目标项目依赖、不启动服务、不执行目标代码、不改目标源码；只有用户明确要求相关验证或实现，并提供所需范围时，才运行或写入。

## 状态边界

结构验证、来源与字节校验、来源事实复核、语义教学复核是不同证据。成功解析、链接存在、哈希匹配或命令退出成功，都不能单独声明教材适合初学者。未经独立教学复核的内容应标为未审或草稿；人工审阅的草稿可以在说明范围和缺口后用于学习，但不等于正式生命周期回执或发布状态。

整本教材的里程碑续写、普通 Markdown checkpoint 示例和跨模型恢复步骤见[中断恢复与模型适配](中断恢复与模型适配.md)。
