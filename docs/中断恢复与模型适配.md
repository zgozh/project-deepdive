# 中断恢复与模型适配

本指南说明如何在长教材写作中保存可恢复进度。checkpoint（里程碑进度记录）使用普通 Markdown 和用户选择的输出目录，不增加 CLI、强制 schema 或后台任务；示例目录与状态只是建议格式，不是本项目运行记录或认证回执。

## 什么时候保存进度

用户明确要求完整教材或多章路线时，先依据真实项目、读者先修和业务关系制定语义书稿计划，再按顺序持续完成。不要在每章结尾无故停下来等待下一次确认。每完成一个有意义的里程碑（例如地图通过核对、一个主题稿完成、一次复核完成），在工作记录中更新一份简短 checkpoint，然后继续路线中的下一项。只在里程碑更新，不逐次编辑或为每次更新重跑检查。

如果缺少继续所必需的项目路径、源码权限或用户决策，宿主拒绝某项操作，可用额度不足，或用户明确要求暂停，就停在依赖该信息的步骤并保存真实状态与明确下一步。不得假称后台会继续运行。源码和输出权限始终以宿主实际能力及用户授权为准。

## 分开保存读者正文和工作记录

可以使用这样的目录形状；路径由用户决定：

```text
<项目学习输出>/
  教材/                         读者直接阅读的语义章节
  工作记录/
    book-plan.md                路线、先修关系和范围
    checkpoints/
      current.md                最近一次短进度记录
    source/                     来源证据或快照（需要时）
    reviews/                    独立来源/教学复核记录（需要时）
```

将供作者核验的原始源码快照、来源记录（provenance）、机器 ID、JSON、检查日志和内部审查状态放在工作记录目录。供学习者阅读的源码摘录仍应放在相应章节正文，并配完整的前中后解释和覆盖所展示范围的适应性行表。写文件前确认输出位置；只需要对话学习时，不擅自创建这些目录。

## Markdown checkpoint 示例

checkpoint 要回答“项目和版本是什么、哪些文件完成到什么状态、当前做到哪里、下一步做什么”。只写当前仍有用的信息，不逐条记录每次编辑。推荐每个主题分别列出正文草稿、来源复核、教学复核和读者复制/发布状态，避免一个总体 PASS 混淆这些状态。

```markdown
# 教材进度 checkpoint

更新时间：<真实日期>
目标仓库：<实际路径；无法确认写 UNKNOWN>
版本与工作区：<真实 commit 和未提交变化摘要；无法确认写 UNKNOWN>
读者输出目录：<实际路径>
工作记录目录：<实际路径>

## 路线状态
- book-plan：<路径；DRAFT / REVIEWED / UNKNOWN>
- 已完成：<主题与文件路径>
- 当前主题：<主题>

| 主题 | 正文路径 | 稿件状态 | source_review | teaching_review | copied_or_published |
|---|---|---|---|---|---|
| <主题> | <路径> | DRAFT / COMPLETE | PENDING / ACCEPTED / NOT_STARTED；记录路径 | PENDING / ACCEPTED / NOT_STARTED；记录路径 | NOT_REQUESTED / NOT_DONE / DONE；目标 |

完成项、当前半成稿和各项复核状态分别记录；复制/发布状态不等于正文或教学接受。

## 仍有效的证据与未知
- 可复用的来源/检查：<证据路径及其精确适用范围>
- 源码变化影响：<已定位影响，或 UNKNOWN>
- 阻塞或需用户提供：<具体事项；没有写“无”>

## 下一步
- <一个明确的最早未完成操作，以及实际读写路径>
```

模板可按工作规模删减字段；保留真实身份和状态分离即可。没有做过的来源核验、教学复核或复制必须标成未开始/待处理，不根据 hash、脚本结果、文件名或前一章节状态推断通过。

## 恢复或更换模型

恢复时先打开 checkpoint、书稿计划、当前章节和必要的来源/复核材料，并读取目标仓库的当前 revision 与工作区变化。比较记录和当前源码，只让实际受影响的证据失效，复用未受影响且仍适用的证据；从最早未完成主题继续。若记录缺失，依据当前可读文件重建“可能进度”，把推断标为 UNKNOWN 并写明依据。已删除文件和从未保存的对话内容不会被 checkpoint 自动找回。

更换 AI 模型或宿主时，也把目标路径、版本、checkpoint、相关章节、当前待办和必要的前序决定交给新会话，并确认宿主加载了同一份 Skill。新模型不自动拥有旧对话上下文，不保证与之前模型给出相同判断；重要事实仍要回到源码与实际记录核验。无需为了跨模型而重写成大段特殊 prompt，上述状态文件和一句普通恢复请求即可。

## 常用恢复请求

```text
请根据这个目录里的 book-plan、checkpoint 和当前教材继续。先核对目标仓库版本/工作区与记录是否一致，说明哪些旧证据仍适用、哪些受源码变化影响；从最早未完成主题继续，按记录中的输出路径写入并在下一个有意义的里程碑更新 checkpoint。不要依赖未提供的聊天历史，不要把草稿、来源通过、教学通过和复制状态混为一谈。
```
