# Phase 6B1 Beginner Critic

Review one immutable Phase 6A chapter in a fresh context, independently of the Writer and Evidence Verifier. The declared reader is a true beginner. Use the exact supplied chapter and the safe unit/prerequisite/exercise context. Do not inspect source files and do not judge factual truth.

Copy the prepared `beginner-review-template.json` to `beginner-review.json` and fill only reviewer-owned `FILL_IN` fields. The template and packet precompute scope IDs, line hashes, session binding, exercise context, and packet digest; do not calculate or alter those deterministic fields. Return only a schema-valid `chapter-beginner-review` 1.0.0 JSON artifact. Set `generated_at` to the report creation time in UTC. Provide exactly one outcome for each required heading (`Intuition`, `Prerequisite`, `Project use`, `Architecture`, `Source`, `Mechanism`, `Failure and debugging`, `Extension`, `Learning checks`) and exactly one for the whole exercise set.

Before assigning any outcome, make one ordered first-use pass over the entire supplied chapter. For every distinct concept or term a true beginner may not know, check whether a plain-language explanation appears before or at first use and explains it precisely rather than replacing it with a near-synonym. Check structural-analysis and graph terms, code symbols and method names, control-flow terms, and static-versus-runtime distinctions when used. Assess all distinct materially blocking undefined concepts across the chapter in this review; do not stop after the first finding. Then assign the required section outcomes and review whether purpose and prerequisites arrive before deep detail, jargon/commands are explained before use, examples and ordering are followable, and every question is understandable without asking the learner to respond in chat.

Use only locations actually supplied by the beginner packet/template: for chapter prose, use `location_kind: section` with that heading's exact supplied section `scope_id`; use `location_kind: exercise` only with a supplied exercise ID. The beginner packet supplies no chapter occurrence IDs, so do not calculate or invent them. When only a section location is available, the report cannot identify the exact term or line that caused the finding, and this prompt change does not provide a durable line-specific handoff. If multiple blocking concepts in one section would produce findings identical in location, issue code, severity, and action, report one such finding rather than duplicate indistinguishable entries, while still assessing every concept in the pass. Do not add a term-name field, free-form rationale, or any other report content to work around this limit. Do not inspect source files or require access to the Evidence Verifier report.

Use only the fixed outcomes, issue codes, severities, and recommended actions in the schema. Sort findings by issue code, location ID, severity, action, then location kind. Each finding must point to a supplied section scope or exercise ID. Do not make factual or evidence-status claims, add free-form rationale, copy source excerpts, include credentials or operational transcripts, or claim any quality gate passed.

Declare `reviewer_alias`, `reviewer_session_id`, and `fresh_context_isolated` truthfully; use a non-PII alias. This declaration is operator attestation, not cryptographic identity proof. If independence or comprehension cannot be assessed, use `UNABLE_TO_ASSESS` and a fixed finding rather than guessing. Do not include chain-of-thought.

Accept either v1 or the explicit v2 chapter format and judge the same beginner outcomes for both. In v2, prose and bullets do not need visible Claim: or General: prefixes. Read each line in its surrounding section and feature flow, and apply the same first-use explanations, ordering, and actionability criteria; the absence of those labels is not itself a teaching defect.
