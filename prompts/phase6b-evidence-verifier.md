# Phase 6B1 Evidence Verifier

Review one immutable Phase 6A chapter in a fresh context, independently of the Writer and Beginner Critic. The packet identifies the exact chapter and snapshot. Inspect only authenticated snapshot bytes for the listed locators; for a `git-tree`, use the exact pinned revision/object reader, never the mutable worktree. Do not execute target code.

Copy the prepared `evidence-review-template.json` to `evidence-review.json` and fill only reviewer-owned `FILL_IN` fields. The template precomputes the session binding, packet digest, occurrence IDs, line hashes, and cited IDs; do not calculate or alter those deterministic fields. Return only a schema-valid `chapter-evidence-review` 1.0.0 JSON artifact. Set `generated_at` to the report creation time in UTC. Cover every listed `Claim:` and `General:` occurrence exactly once and in order. For each claim, check the exact sentence against its existing claim/evidence IDs, locator, and evidence level. E1/E2 syntax facts do not establish runtime behavior. E6 is inference, never verified fact. Unknown or inaccessible source stays unknown. A `General:` line must be either `GENERAL_TEACHING` or `PROJECT_FACT_UNMARKED`; the latter requires a finding and `MARK_AS_CLAIM_OR_REWRITE_AS_GENERAL`.

Use only the fixed outcomes, issue codes, severities, and actions in the schema. Sort findings by issue code, location ID (empty for this report), evidence ID (empty when absent), severity, then action. Positive claim outcome is allowed only for the existing `SUPPORTED` claim with eligible E0–E5 evidence and no E6. Do not create or upgrade evidence, assert semantic entailment as mechanically proven, judge beginner readability, or claim G08/G09/full Phase 4 passed.

Declare `reviewer_alias`, `reviewer_session_id`, `fresh_context_isolated`, and `direct_source_inspection` truthfully; use a non-PII alias. These declarations are operator attestation, not cryptographic identity proof. If inspection or isolation cannot be established, use `UNABLE_TO_ASSESS` for affected results or set the corresponding declaration false. Do not include free-form rationale, source prose, excerpts, credentials, absolute paths, model transcripts, or chain-of-thought.

## v2 occurrence interpretation

Accept either the existing v1 chapter or the explicit v2 format. In v2, a supported claim marker at the end of a prose or bullet line makes that complete physical line a CLAIM occurrence; without the marker, that complete line is a GENERAL occurrence. Do not require visible Claim: or General: prefixes. The normalized GENERAL occurrence list contains every uncited v2 prose or bullet line, not just lines that look like general teaching. Check each complete line, including bullet text, for an unmarked project-specific fact; report PROJECT_FACT_UNMARKED when needed. The line hash and occurrence ID bind the exact physical line, including its bullet prefix and optional claim marker.
