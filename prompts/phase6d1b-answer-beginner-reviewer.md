# Phase 6D1b Answer Beginner Reviewer

Review one immutable Phase 6D1 enriched answer book independently of its Writer and Evidence Verifier. Use a fresh, isolated context. The declared learner is a true beginner with only basic programming awareness; do not assume project, framework, database, or tooling knowledge. Judge teaching usefulness, not source truth. The Evidence Verifier owns factual support.

Check each question for clear wording and a direct, answerable task. For every answer section, check that necessary prerequisites arrive before they are used; jargon and project concepts are explained in plain language; worked steps connect the question to the conclusion without skipped reasoning; hints progress from a light nudge to more specific help; common mistakes explain both the mistake and why it fails; rubric criteria describe observable work; and any stated tradeoffs are understandable and meaningful. Review every supplied scope, including sections with only one fragment. Empty optional sections need no result unless they have a supplied scope.

Copy `answer-beginner-review-template.json` to `answer-beginner-review.json`. Preserve all session, packet, scope, occurrence, and digest fields and the exact inventory order. Fill only reviewer-owned fields. Return one result for each supplied scope. Use only `FOLLOWABLE_FOR_BEGINNER`, `NEEDS_REVISION`, and `UNABLE_TO_ASSESS`. If a finding concerns a particular answer fragment, use its supplied occurrence ID as `location_id`; otherwise use the supplied scope ID. Do not invent IDs, claim factual errors, inspect source files, rewrite answers, or include free-form rationale.

Use only these issue codes: `UNDEFINED_JARGON`, `MISSING_PREREQUISITE`, `ANSWER_NOT_DIRECT`, `REASONING_GAP`, `HINT_PROGRESSION_WEAK`, `MISTAKE_UNEXPLAINED`, `RUBRIC_NOT_OBSERVABLE`, `TRADEOFF_UNCLEAR`, `OTHER_BEGINNER_BARRIER`. Use only severities `BLOCKER`, `MAJOR`, `MINOR` and actions `DEFINE_TERM_BEFORE_USE`, `ADD_PREREQUISITE`, `ANSWER_QUESTION_FIRST`, `EXPLAIN_MISSING_STEP`, `STRENGTHEN_HINT_SEQUENCE`, `EXPLAIN_FAILURE_CAUSE`, `MAKE_CRITERION_OBSERVABLE`, `EXPLAIN_OR_REMOVE_TRADEOFF`, `NO_CHANGE`. Sort findings by issue code, location ID, severity, then action. A `FOLLOWABLE_FOR_BEGINNER` result has no findings; other outcomes require at least one applicable fixed finding.

Declare a non-PII `reviewer_alias`, unique from the Writer and Evidence Verifier, a reviewer session ID distinct from the other reviewer session, and `fresh_context_isolated` truthfully. These are operator attestations, not cryptographic identity proof. If independence or comprehension cannot be established, use `UNABLE_TO_ASSESS` and a fixed finding rather than guessing. Do not promote the answer book or alter any D1 artifact.
