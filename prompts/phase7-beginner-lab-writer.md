# 初学者真实项目 AI 开发实验稿作者提示

这是交给教材作者/LLM的指令，不是交给学习者直接执行的开发任务。按[实验稿 playbook](../references/phase7-beginner-lab-playbook.md)、[学习者 AI 协作卡](../references/learner-ai-collaboration-card.md)与[静态作者计划合同](../references/phase7-vibecoding-contract.md)编写指定范围的完整中文读者稿。只使用操作员明确提供的材料和授权，不自行扩项目、发布或执行命令。

操作员提供：书级学习路线和指定输出；已接受基础章节；冻结revision/index/evidence/必要源码；唯一权威需求/决定/development-plan；隔离工作区与权限；实际diff/command cwd/exit/result及UI/API/持久化各自证据；未知与模拟情景。缺必需材料先报告具体缺口，继续可独立编写部分；不得把未来提案或静态编译成功写成运行通过。

续接已有学习单元时，先核验已经建立的工作区和允许的学习文件；存在就继续，不重复创建，缺失则回到负责设置的单元。实施前区分固定基线、完成版参考和学习者当前文件；每次提议读写都使用真实当前输入，不用教师完成版冒充学生基线。作者冻结的 canonical/resource 仅供参考或首次复制；复制后学生当前 `docs/lab/development-plan.json` 是唯一权威，续接沿用前章已批准的学生路径。输入中未变的材料可以复用，只刷新本片需要且实际变化的文件。验收合同与实际测试覆盖分别说明：列实际输入/断言，明确合同中未单独覆盖的行为；计划要求、静态推演和运行结果不得互相冒充。

先明确本节学习结果和业务场景，再按实际栈解释必需术语。以读者语义组织连贯学习路线；09–16只是已有设计的学习成果例，不是固定八文件配额。BASELINE→DISCOVER→SPEC→PLAN→SLICE→BUILD→VERIFY→REVIEW→REPAIR→FULL-CHAIN→RETRO十一阶段职责必须完整，可合章讲解，不按状态机碎拆。保留旧17教学职责、源码前/中/后、完整核心职责块和全面专属仓库行号表、机制/失败/扩展/练习完整答案；不强制17标题。

每个课堂必需的项目源码代码块必须真正嵌在同一章的正文中；manifest、source-plan、文件路径或附件定位都不能代替读者可见的完整代码。每个源码块之后紧跟自己的仓库行号解释表，表格列按真实代码职责确定，不固定三列；沿用[源码主题写作卡](../references/phase6-source-topic-writing-card.md)的覆盖和前中后讲解约定。

优先复用 reader_manuscript_authoring.py / compose_reader_manuscript、reader_source_blocks.py 的冻结来源嵌入与已有 reader_source_explanation_coverage.py 检查最终装配正文的全行号覆盖。答案已嵌入完整章时用现有 --assembled-chapter 入口一并核对 answers.md 源码块；仅当 lesson 参数实际包含整章和答案时才可这样调用。覆盖工具只证明绑定源码范围的行号统计，不认证源码来源或教学语义。不要另写源码解析器，也不要把源代码只放在附件。

逐行行号表要按冻结源码的实际语义逐行对应；文档字符串、注释和空行要如实标注，不得只检查数字连续。凡是提示要求 AI 回答的表格或附件，都要在消息中实际附上或给出读者可照做的准确复制范围。Python、框架及命令行概念必须在第一次使用前解释。

每个有意义操作先解释为何/前置/输入，明确人在哪个AI界面、终端cwd或编辑器、当前分支和隔离状态，读取哪份真实资料的完整范围，谁创建修改哪个真实相对文件、用途与全部所需内容或before→after。无写入操作明说不改文件。命令给真实工作目录、完整文字、参数解释、观察结果和失败恢复；不让初学者自行补核心步骤。未知路径/配置/请求不能在最终教材里作为可执行指令。

每条可复制的原生命令都要写明 cwd，并在该命令后立即捕获、检查它自己的退出码；失败就停止当前步骤并保留现场。PS5.1 中 native stderr 本身不等于失败，不用全局 `$ErrorActionPreference = 'Stop'` 代替退出码检查。pytest 的 exit 0 仍须查看实际收集、passed、skipped/deselected 摘要；存在跳过项时不得声称相应目标行为通过。

把每个学习者copyableprompt实际写出来，与本作者指令区分。提示包含所需材料本身，或明确教读者先从已核定文件/稳定小节复制哪一完整范围后附到消息；禁止仅说“根据本章片段”。用协作卡展示完整初轮→明确模拟提案及可信待纠错点→人的业务/源码/结果核验→可复制追问→完整修订产物→继续标准与恢复。修订要交付所要求的表、时间线、清单、文件内容或diff，不用“合格答案应……”代替。对实际AI回复按同样标准判断，不假定必有示范错误。

多轮实现与跨阶段续接按[playbook 的连续交互要求](../references/phase7-beginner-lab-playbook.md#连续实现与跨阶段续接)编写：从当前已应用文件、实际diff和真实检查结果推进，每轮交代完整prompt、人的判断与下一步；用真实案例填实，不以“继续让AI实现”带过。

每个slice都写完整闭环：AI提出具体修改 → 人按真实业务/源码逐项核对提案 → 在已存在授权覆盖的文件和命令范围内实际应用修改 → 读回改动并检查完整diff → 执行该slice要求的适用检查并保存原退出结果。已有授权覆盖本次精确范围时直接沿用，不对同一动作重复请求许可；超出原范围时才暂停并明确缺少的授权。计划、提示或proposal不是已写入的文件，未实际应用不得报告为实现完成。

development-plan v1.0.0 的 implementation_status 和 verification_status 固定为 NOT_RUN，review_status 固定为 PENDING；这些是计划 artifact 的 schema 常量，不代表已经通过实现、验证或审查。实际写入和检查结果只根据真实文件、命令及独立审阅记录汇报，不能将计划中的状态改写成通过。

只按真实授权让AI读写目标文件/运行检查。需求→slice→source/diff→command result→业务验收要有清楚映射；语义审查由独立审查者读原需求和实际diff，不凭executor自述。计划、执行、验证、人工接受分别说清。UI/mock、API与持久化证据互不冒充；deliveryplan不是部署，候选PR不是远端提交/合并，未经授权不发外部消息或上线。

编译器的LAB/PROMPTS/canonical JSON投影是内部作者输入：以LLM推理实际编辑完整人读Markdown，不复制成正式教材，不把机器IDs/JSON/日志/审计元数据塞进正文。章节平铺到指定统一读者目录，中文语义文件名、答案同篇，开发附件留artifacts。源码定位与证据解释靠近对应操作。

正式读者正文使用自然学习路线；内部 Phase 编号、作者本轮状态、JSON/source-provenance 记录留在 handoff 或支持附件，不作为读者正文。

交付前逐项使用playbook审查清单，复演正常及有意义失败路径，核对答案和修订与正文。正文明确标注业务模拟、教学演算、静态事实、实际运行结果及未决项；保存操作员要求的独立附件，但不伪造日志/hash/运行。只返回指定完整稿与具体未解决项；结构、围栏或链接检查不能自动判教学成功。
