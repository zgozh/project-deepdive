# Phase 6D1b Answer Evidence Verifier

Review one immutable Phase 6D1 enriched answer book independently of its Writer and the Beginner Reviewer. Use a fresh, isolated context. Follow the exact answer-evidence packet and the authenticated snapshot it binds. This is a reviewer-authored judgment; the CLI proves package identity and coverage, not factual support.

Inspect the original pinned source for every `CLAIM` answer fragment and compare the exact wording and scope with the listed eligible evidence. A valid claim ID, evidence ID, or eligible evidence level does not prove that the answer is supported. Treat inference as inference, do not generalize beyond the inspected source, and mark a source locator unavailable or out of scope when it cannot establish the statement. For every `GENERAL` fragment, decide whether it contains a project-specific assertion that should be marked as a claim or rewritten as general teaching. Inspect all listed occurrences, including worked steps, hints, common mistakes, rubrics, and tradeoffs.

For a `git-tree` snapshot, inspect only the exact pinned revision through the snapshot-aware reader; never substitute the current worktree. Never execute target code. The packet contains no source bodies: do not copy source text, secrets, credentials, absolute paths, transcripts, or free-form rationale into the report.

Copy `answer-evidence-review-template.json` to `answer-evidence-review.json`. Preserve all session, packet, occurrence, claim, evidence, and digest fields and the exact inventory order. Fill only reviewer-owned fields. Return one result for every listed occurrence. Use only these outcomes: `CONSISTENT_WITH_CITED_EVIDENCE`, `NEEDS_REVISION`, `UNABLE_TO_ASSESS`, `GENERAL_TEACHING`, and `PROJECT_FACT_UNMARKED`. A positive claim outcome requires direct inspection and an evidence ID already listed for that occurrence. A `GENERAL` fragment with an unmarked project fact requires a `PROJECT_FACT_UNMARKED` finding and `MARK_AS_CLAIM_OR_REWRITE_GENERAL`.

Use only these issue codes: `CLAIM_UNSUPPORTED`, `CLAIM_OVERGENERALIZED`, `E6_PRESENTED_AS_FACT`, `CITATION_MISMATCH`, `SOURCE_SCOPE_MISMATCH`, `LOCATOR_UNAVAILABLE`, `PROJECT_FACT_UNMARKED`, `OTHER_SUPPORT_GAP`. Use only severities `BLOCKER`, `MAJOR`, `MINOR` and actions `NARROW_OR_REMOVE_CLAIM`, `ADD_OR_FIX_REFERENCE`, `LABEL_AS_INFERENCE`, `MARK_AS_CLAIM_OR_REWRITE_GENERAL`, `NO_CHANGE`. Findings must use only eligible evidence IDs already attached to the occurrence; use `null` when a finding is not tied to one. Sort findings by issue code, evidence ID (empty when absent), severity, then action.

Declare a non-PII `reviewer_alias`, unique from the Writer and Beginner Reviewer, a reviewer session ID distinct from the other reviewer session, `fresh_context_isolated`, and `direct_source_inspection` truthfully. These are operator attestations, not cryptographic identity or semantic proof. If source inspection or isolation is unavailable, set the corresponding declaration false and use `UNABLE_TO_ASSESS` where appropriate. Do not change the answer, add evidence, rewrite claims, or promote any status.
