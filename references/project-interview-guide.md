# 项目相关面试练习指南

面试练习从学习者已经学过的一条项目工作流、对应知识图和真实源码证据生成连续追问。它是提示驱动的自然语言协作：AI 在当前可用的项目材料里查找依据并与学习者对话，不意味着仓库有独立 Interview Engine、题库 CLI 或自动评分器。

开始前选定一个已完成的工作流章节，核对所用仓库 revision、真实业务场景、知识图、调用图、证据和源码。面试问题应引用这条流程中已学过的事实；未学过的目标先标为未覆盖，不推断学习者已经掌握。

## 先设定能追溯的问题锚点

为一个问题组确定业务场景、参与者、输入、可观察结果和要考查的已学主题。然后从当前项目证据找到对应业务能力、文件、符号、调用者和被调用者、关键分支及测试。问题与追问都能回到这些锚点。

如果没有真实源码或证据，不从类名、文件名或框架惯例猜调用链。先请求缺失的已学章节、知识图、证据或源码范围，或把该主题标为待定位。推测可以作为设计假设提出，但必须明说它是推理而非项目事实。

新术语、缩写和通用知识先用直觉、小例子和完整英文名解释，再说明它为什么与本问题相关。可引用与实际语言、框架和协议相符的官方资料；通用机制和项目实测事实要明确区分。

## 让问题逐步深入

可按项目场景选择以下追问方向。它们不是每题必答的固定12章；前一层回答揭示的误解、证据和兴趣决定下一问。

1. **L1 项目目的**：学习者试图解决什么问题？
2. **L2 业务工作流**：谁触发流程，输入和结果对使用者意味着什么？
3. **L3 架构**：哪些真实组件接力，接口和数据在哪里交接？
4. **L4 源码**：哪段完整源码做了关键判断、转换或返回？
5. **L5 框架机制**：项目中的框架或协议为何产生这个效果？
6. **L6 底层原理**：相关语言、运行时或系统原理如何解释这个机制？
7. **L7 失败与调试**：坏输入、依赖失败或异常沿哪些分支传播？
8. **L8 并发与性能**：只在已学场景适用时，追问共享状态、同步、瓶颈和证据。
9. **L9 规模扩展与设计取舍**：流量或数据规模变化时，哪些成本、瓶颈和设计边界会改变？
10. **L10 扩展**：从哪个已证实的接缝增加能力，哪些调用者和测试受影响？
11. **L11 挑战与反驳**：质疑前述假设，要求学生给证据或比较方案。
12. **L12 重设计**：基于目标、证据和约束提出有边界的替代设计。

完整规格的 Interview 追问从 L1 到 L12；其中源码教学自身的 L0–L4 是另一组深度概念。不要把源码层级当成面试题序号，也不要因面试路径可继续加深，就要求每个主题走完全部层级。

问题从目的、业务开始，只有学习者已经能解释当前层的概念和项目材料时，才继续向源码与机制深入。若学习者说不清先修概念，暂停追问，补一个简明定义和例子，再让他用当前流程解释。无法补证时明确停在未知，不靠连环追问掩盖证据缺失。

## 进行实时问答

一次只问一个主问题。根据学习者回答选择紧接着的一条追问；让他说明用的是业务输入、知识图、源码、测试还是推断。不要在作答前泄露参考答案或把标准答案改写成提示。

评分看推理与证据的连贯性：是否讲清业务目的和数据流，是否找对源码职责，是否跟住分支、返回及错误处理，是否区分事实与推断，是否能讨论设计边界。术语不熟时先教前置知识，不把表达方式或背诵标准措辞当作项目能力。

学生回答后先指出正确且有依据的部分，再说明具体缺漏、错误或未知，给最小必要的源码/概念提示，并继续同一问题链。若其回答提出合理替代设计，不因与范例不同就判错；请比较适用条件、成本和可验证证据。

## 编写自学问题组与完整答案

作为教材写作时，围绕已学工作流组织少量相关题组，而非把每个专业术语都变成一题。每组标明先修章节、业务与源码锚点、问题目的、逐层追问方向、适用的失败或设计场景，以及本题涉及的必要通用概念。

自学版本应在练习之后提供完整参考答案、短提示、评分依据、可接受的不同答案和证据定位；答案解释为何成立，并指出其依赖的输入、条件和边界。面试模拟时这些材料作为隐藏答案，等学习者回答后再逐项反馈。

如使用标准视图和教师视图，教师视图可额外列出答案与评分细则，但学习者仍须拿到可独立复习的完整答案。这里的教师视图仅是内容组织方式，不表示正在开发授课书或独立教学平台。

避免百科式八股罗列。对确有关系的基础问题，按以下顺序讲：白话定义和常用英文名 → 为什么此项目会遇到 → 真实源码落点 → 执行机制或数据变化 → 替代方案与适用边界。没有项目来源的部分明确标为通用知识。

题目要使用当前项目的语言、框架和协议证据。不要假设一个 Java 服务会用到 Python 装饰器，或任何项目一定存在 Agent 注册、缓存、队列和数据库事务。

## 复核与完成条件

逐题检查目标是否在已学范围内，业务问题是否指向具体流程，后续问题是否建立在前一答上，来源定位是否真实，答案是否跟随实际返回和异常边界。把未覆盖题目移出当前面试组或标作待定位。

实际面试结束后记录学习者的真实回答、依据和误区；没有进行的面试不能写成实测表现。对项目理解的结论应能回到素材和证据，对通用定义则列明解释或官方来源。

当题组来自已学工作流、包含项目特定问题、并通过源码、机制、失败、设计或扩展方向之一形成连贯追问时，才满足 AC-16、R-033 和 G17 的基本要求。泛化题目加上项目名、随机八股题堆叠、静态列表通过格式检查或编造调用链都不算通过。
