# 初学者真实项目 AI 开发实验稿 playbook

本流程服务跨项目自学：已有教材先教会读者从整体到具体理解项目，实战再在同一项目完成有界新需求。使用[作者提示](../prompts/phase7-beginner-lab-writer.md)和[学习者 AI 协作卡](learner-ai-collaboration-card.md)，不新增平台、SDK、provider或特定模型依赖。卡片规定完整交互职责，本文件只补真实lab制作与十一阶段的目标、产物和检查。

## 准备真实资料与可操作实验

先复用已有foundation/evidence和已接受的学习解释，按本任务窄补未知，不重扫全库或重认证未变证据。选定业务情景、真实扩展点与有界验收；虚构组织/业务情景明确标为教学模拟，不把已有能力说成缺功能。

核对冻结revision、原工作区状态、隔离根、可读/可写范围及允许命令。在干净隔离baseline上练习，原用户checkout保持保护；若无法创建隔离区，准确报告未执行，不悄悄在原目录改代码。作者将实际根和命令填进正文，项目内文件采用真实相对路径。planned CREATE文件可计划新增，不得伪装为baseline已有事实；现有工具拒绝某输入时依合同诊断，不造index/evidence绕过检查。

唯一权威development-plan保存需求/决定/切片与检查定义；Markdown是教学/投影视图，不另造相互可变的决定源。按[编译合同](phase7-vibecoding-contract.md)生成的新LAB/PROMPTS/JSON是内部作者资料，由作者解释并编辑成人读正文；静态编译的NOT_RUN/PENDING状态不证明实施/教学通过。

实施按完整小增量推进：spec/技术设计/文件slice→实际实现→适量检查→真实失败定位与最小修复→受影响重验→独立diff/行为审查。已有有效检查在未受影响时保留。将UI、API、持久化及异常回程连起来讲，但每一面的实际证据独立记录；有mock就讲其替换边界，没有后端/DB运行就保留未知。最后写候选交付、观测/回滚与人工验收计划，未经实际部署不说部署完成；RETRO仅反馈已确认通用问题。

## 十一阶段如何教与验

每行的产物是责任而非强制新增文件。作者将证据支持的实际材料、完整内容、cwd/界面与命令填进相应操作；按共用卡写why/前置/输入→人和AI动作→完整交互→检查→恢复。不把作者发给LLM的“编教材”指令混进学生的开发prompt。09导读/基线、10需求、11扩展点、12技术设计、13切片、14首个增量、15检查/修复、16交付/复盘是语义学习成果例，可以合章或拆分，不固定八篇。

| 阶段 | 人与AI的具体任务/可检查产物 | 继续标准与恢复 |
|---|---|---|
| BASELINE | 人提供真实根/revision/status/环境与授权；AI解释工具能力、诊断前置和最小基线命令，人核对每个参数并保存真实输出 | 知道当前状态和允许写范围；缺环境定位实际配置/依赖，不编默认凭据，不把旧检查当新运行 |
| DISCOVER | 人选本任务必要源码/现有能力/测试seam；AI逐交接画扩展点与未知，人对真实声明/调用核验 | 能说明已有能力与待改行为；找不到则窄补证，不杜撰文件或接口 |
| SPEC | AI从业务输入输出提出MVP/术语/正常空异常验收，人按实际用户场景裁定范围 | 可用具体输入判断是否满足；需求漂移回到原目标/决定，不随AI扩题 |
| PLAN | AI提出兼容/数据API/权限/依赖方案与可选spike/ADR，人比较已有接口/维护成本 | 决定和理由一次写入权威plan；未定技术点先有界试验，不装重流程 |
| SLICE | AI给有依赖顺序的vertical slice、允许现有/新增文件、保护范围、接口和检查；人逐文件核对 | 一个增量能闭环且每验收可追check；未知path回查，多个writer不改同文件 |
| BUILD | 人在已核定隔离分支授予精确写范围；AI交完整文件或具体diff，人解释关键变量/分支/机制和调用处 | 变更对应slice且可理解；意外变更停该依赖并回到基线diff，不自动提交/上线 |
| VERIFY | AI设计正常/空/错误/兼容检查，人依真实cwd执行获准命令/操作，AI解释实际stdout/exit/可见行为 | 按检查的真实范围判断，mock不证明DB；失败保留原结果进入REPAIR |
| REVIEW | 独立AI/审查者读原spec+完整实际diff/源码+检查结果，人核对具体问题/证据并处理误审 | 每阻塞点有依据或有事实反驳；多数同意不当真，不只读executor摘要 |
| REPAIR | AI按一个证据确认的问题提出最小修复，人比较before→after并重验受影响证明 | 原需求仍满足且相关失败已解决；新扩题退回PLAN，不无限盲循环 |
| FULL-CHAIN | 人走UI→client→API→service→授权/查询或存储→UI回显/异常，AI整理各面证据与未覆盖；写候选CI/交付/回滚方案 | 用户可观察路径与限制明确；未实际部署/API/DB的面保留pending，不以构建当业务接受 |
| RETRO | 人解释学到的机制与决策，AI整理故障原因/有效修法/复用边界及下一练习完整答案 | 教训有真实依据，不把项目路径放通用contract；最终接受按适用门槛单独判定 |

## 可复制的学生提示框架

这些是作者替换真实材料的框架。**最终教材须先填完本节“任务说明、资料、许可、检查”再交学生**，不能让学生补未知模块/版本/类型。学生操作：在教材对应稳定小节逐块选中从区块标题到结束的全部文字，按下面标记顺序复制到AI新对话末尾；确认没有缺少源码结尾、配置字段或实际失败输出，再发送。文件较长时作者预先给获准的完整职责范围，不能只给“自行找相关代码”。只读步骤不新建文件；写入步骤由作者在许可区给真实文件和全部所需内容/具体diff。

初轮复制提示（四个材料区必须随消息一起提供）：

```text
请作为我的开发学习协作者，只依据本消息附带资料完成“任务说明区”的当前阶段任务。
先用通俗语言解释资料中首次需要的术语，再说明输入如何经过已有代码/机制得到结果。
先提出可核验方案，不先改文件或运行命令；只有“许可区”明确授权后才可在指定隔离范围动作。
区分现有事实、建议新增、教学模拟和未知。不要编造文件/接口/配置或扩大业务目标。
按“任务说明区”交付完整产物：需要表/两分支时间线/清单/文件内容/diff就实际给出，不只描述应有什么。
列出我能按“资料区”核对的具体依据与“检查区”要求的观察结果；未运行的检查不写通过。
如材料缺失，指出缺哪一段及它阻止哪一个结论，不猜答案。
我会比较输入/范围/分支/兼容或权限中与本任务有关的项，再决定是否授权下一步。
---任务说明区（复制教材本节已经填好的目标、阶段、输入、所需产物）---
---资料区（紧接此标记复制教材指定完整材料及真实定位）---
---许可区（复制实际cwd/界面/分支、可读写文件、允许命令和保护边界）---
---检查区（复制业务验收、实际结果或尚未运行状态、继续与恢复标准）---
```

作者须在上述每个标记后放入实际内容，或紧接模板给一份四区完整填好的消息。框架不是可空发送的成品prompt。材料已在当前AI会话可见仍须明确指出哪个已提供区块，而不是依赖AI猜“本章”。

追问/修订复制提示（教材须提供具体待核验项；若真实回复无示范错误，就比较关键选择与证据）：

```text
请复核刚才的方案，目标、资料与许可仍按我上一条消息的四区内容，不能扩大写范围。
我会在本消息末尾附“核验反馈区”：逐项原建议、真实材料/实际输出、对应差异和需要修订的产物。
请先解释各项反馈是否由这些材料支持；不支持的项说明具体原因，不能仅同意我。
对确认的问题给完整修订后的表、时间线、清单或文件/diff，并逐项说明before→after和原因。
给最小受影响重验与明确继续标准，所有命令遵守原许可；不执行未授权命令、不伪造运行结果。
缺证的事实继续标未知。若无法完成，指出恢复应读取哪份已提供材料及尚缺什么。
---核验反馈区（复制本节实际反馈材料，或贴我对真实回复逐项比较的结果）---
```

作者为每个有意义步骤提供完整模拟提案、人的具体核验、完整修订示例与答案；不强求每句一个step、不强制每步新文档。共用卡已有完整无语言绑定的教学演算，可复用其交互方法而非将演算冒充项目案例。

## 连续实现与跨阶段续接

把多轮实现讲成一条真实操作链：每个有意义阶段说明读者所在的章节/界面或终端、当前任务和给AI的材料；用上面的四区框架填出完整首轮与下一轮prompt。读者对照实际AI回复和来源证据，判断采纳、追问还是退回设计；模拟与真实回复不一致时，以真实材料和实际结果核验，不要求真实回复复现模拟。再按授权操作，读回当前文件与实际diff，执行本轮检查并看真实输出。模拟提案只用于练习判断，不能代替实际回复、已应用修改或检查结果。

用同一案例展示“方案获准 → 可执行实现 → 读实际diff → 根据命令输出反馈 → 针对性修复或进入下一增量 → 独立审查/全链路复核”。每轮都从当前已应用文件、真实diff和检查状态出发；若证据支持且增量完整则继续，问题局限于一个已证实缺陷就缩小修复并重验，需求或方案依据不足则回到设计。下一轮只带影响当前判断的实际命令输出/退出结果和对应改动，不用无关日志代替证据。轮数由真实工作决定，不强凑轮数、失败或新增文件。跨阶段或开启新对话时，提示中交接已批准的计划、当前基线/文件、实际diff、命令与退出结果、尚未解决的问题及原许可；不得用旧提案或教师完成版描述学生当前状态。

作者须把这条链按真实案例填进最终教材：每轮给出读者可复制的完整prompt、预期产物/观察点、对真实或明确标为模拟的回复所作的人类判断，以及由此决定的下一步。不能用“继续让AI实现”概括关键轮次；共用prompt框架可引用本节，不必重复全文。

## 从真实失败迁移诊断方法

- 终端先核对shell、cwd、完整命令与实际报错。Windows Maven的`-D`参数若被PowerShell分词，先按该shell将完整参数作为一个引号包裹的字面参数，再在实际依赖环境重验；不从解析失败推断业务代码坏，不把未经运行的示例命令写为通过。
- 测试夹具若框架初始化失败，读取堆栈定位实际configuration/registry类型与构造路径，再和目标依赖版本及现有测试seam比较。某次MyBatis夹具需要`MybatisConfiguration`只说明那份版本/构造路径的修法；不可推广为所有项目的固定配置，不删断言掩盖错误。
- UI重复请求先核对mount、effect、实际请求次数和筛选事件：开发StrictMode可能有两次mount，必须分开记baseline mount与本次用户动作。不能把两次mount直接指控为source filter触发double fetch，也不能假定所有重复请求都是StrictMode。用可定位调用/事件日志或mock断言区分，再窄修真实问题。

以上是有证据再分类/最小修复的方法，不是任何项目的普遍故障事实。真实命令、失败日志与修复记录留开发附件，正文在对应操作附近解释可观察差异。

## 独立读者稿审查清单

- 内容先行：用完整读者消息检查每个初轮/追问确有材料或明确存在资料/范围；修订实际交付完整产物，没有虚构手册、模块、版本/类型或因插入失效的行号引用。
- 初学者顺序：why/术语/前置先于操作，业务场景→架构→完整源码→机制→失败/扩展连贯；核心代码块完整，前中后解释、专属行号表与正常/失败推演保留。
- 可跟做：每个实质操作有实际界面/cwd/分支、读写文件/内容/创建者、命令参数解释、结果与恢复；读者能预测、比较和解释diff，不只是抄prompt。
- 工程边界：空值/错误/兼容/权限按本功能实际需要检查；独立审查原需求与完整diff；误审用证据处理，修复不改变原目标；已有效检查不重复跑。
- 证据诚实：模拟与实际结果分开，计划/编译/构建/mock不冒充后端DB、live UI、部署或人工接受；未覆盖面与失败保留，来源/行为/教学分别审查。
- AI协作：初轮、人的核验、追问与完整修订/继续标准齐全，真实回复可不同；不是只让AI解释一次，也不把11阶段强塞每源码小节。
- 读者成品：指定统一目录平铺、清爽中文语义文件名，练习和完整答案同篇，源码定位就近，机器ID/JSON/原始日志留artifacts；投影稿不能直接发布。

最终审查独立读完整成品与答案，复演正常及至少有意义的失败路径，绑定实际字节/范围与未覆盖。结构、链接、围栏和行号检查仅证明各自范围，不能自动判教学/G15成功。
